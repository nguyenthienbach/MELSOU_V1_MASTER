# Production configuration checklist

The app is structurally prepared for Cloudflare Workers static assets plus `/api/*` endpoints. It is not safe to accept payments until all items below are complete and verified.

## 1. Supabase PostgreSQL

Apply all files in `supabase/migrations/` to the intended Supabase project in filename order, including `202609080001_backend_completion.sql` and `202609080002_native_auth_voice.sql`. The latter creates the common application principal, native credential/session/email-challenge tables, migrates existing Google identities to that principal, repoints identity foreign keys, and adds private voice/order-selection/cleanup state. Audit FK/RLS behavior on a staging database before production. The earlier `projects_owner_xor_guest_check` is installed `NOT VALID`; audit legacy rows and then validate it. Set a trusted `OWNER_USER_ID`; `OWNER_EMAIL` remains only for an optional verified Google identity. Never accept an Owner role from browser input.

## 2. Cloudflare Worker

Create/deploy this Worker using `wrangler.jsonc`. Apply the storage migration to create the private Supabase Storage bucket `melsou-assets`; the service-role key is Worker-only and browser clients receive no public storage policy. Enable the configured `IMAGES` binding so image uploads can be decoder-validated and converted into metadata-free derivatives; voice recordings remain private original audio objects. Set `VOICE_MAX_DURATION_SECONDS` only from the approved hardware/fulfilment workflow. Production voice upload also fails closed until a server-side decoder/probe adapter is configured through HTTPS `VOICE_PROCESSOR_URL` and secret `VOICE_PROCESSOR_TOKEN`; the adapter must verify the actual audio stream, MIME and duration. Add a Cloudflare Rate Limiting binding named `API_RATE_LIMITER` with an owner-selected unique numeric `namespace_id`; native registration/login/recovery, uploads, invites, tracking and webhooks fail closed in production without it. Configure sensitive values as Cloudflare Secrets, including the internal render token and email/voice adapter tokens. [Workers secrets](https://developers.cloudflare.com/workers/configuration/secrets/), [Rate Limiting binding](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/), [Images binding](https://developers.cloudflare.com/images/optimization/binding/) and [static assets](https://developers.cloudflare.com/workers/static-assets/).

## 2A. Native auth and recovery

Native sessions require no external identity credential, but do require HTTPS, the migration above and the rate-limit binding. Configure `APP_BASE_URL`. Email link/recovery stays disabled until an owner selects a transactional email adapter and sets `AUTH_EMAIL_DELIVERY_URL` plus `AUTH_EMAIL_DELIVERY_TOKEN`; the adapter receives one-time action URLs server-to-server. Google OAuth is optional. Test username uniqueness/concurrency, password verifier cost, five-failure lockout, cookie flags, expiry/revocation, unknown-email enumeration resistance, email verification and recovery-token single use.

## 3. SePay

Set `SEPAY_MODE=TEST` for the classroom/demo environment. Set it to `LIVE` only as part of an explicitly approved production go-live; neither mode creates a fake paid transition. Create a public HTTPS webhook at `https://<domain>/api/sepay/webhook`; choose **HMAC-SHA256**, never unauthenticated webhooks. Store the generated key as `SEPAY_WEBHOOK_SECRET`. The worker validates raw body, `X-SePay-Timestamp`, HMAC and a five-minute replay window before calling the transactional Supabase RPC. It deduplicates on SePay event `id`, matches configured bank account, payment code, exact amount and expiry, and only transitions an awaiting order to `PAID` on exact match. SePay documents this signing input as `{timestamp}.{raw_body}` and requires `{"success": true}` response for successful receipt. [SePay authentication](https://developer.sepay.vn/vi/sepay-webhooks/xac-thuc), [payload and response contract](https://docs.sepay.vn/tich-hop-webhooks.html), [Test Mode](https://docs.sepay.vn/test-mode.html).

## 4. Required additional services

Configure private Supabase Storage for upload originals/previews/voice recordings, native-auth rate limiting, the voice decoder/probe adapter and the real print-vendor profile before enabling checkout. Google OAuth is optional. The code deliberately blocks checkout at `TBD_PRINT_VENDOR` until the print partner supplies values. After the verified Owner account signs in, activate the vendor profile through `POST /api/owner/print-profiles`; that Owner-only route validates all dimensions, DPI and color profile and deactivates any earlier profile. Google Drive is archive-only through the scheduled archive outbox; Google Sheets is reporting-only through the scheduled reporting outbox. Neither ever becomes a transactional source of truth. Drive archive files carry a deterministic `melsouArtifactKey` app property, and Sheets column A stores the reporting-outbox ID; preserve both fields because they make uncertain external retries idempotent.

## 5. Go-live gates

Run real native register/login/logout/lockout/session/recovery and optional Google failure recovery; apply/inspect RLS with anonymous, native customer, Google customer and owner identities; run SePay Test Mode HMAC forged/replay/duplicate/amount/reference/late-payment checks; verify authenticated and guest Supabase Storage authorization; perform remote image and voice-container upload checks; verify voice draft cancel/commit/order pin/cleanup retention, checkout idempotency, tracking rate limits, blog OWNER writes and account persistence; and complete an actual voice-chip plus print sample with approved hardware/vendor profiles. Keep production in preview/demo mode until every gate passes.
